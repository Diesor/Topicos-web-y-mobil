# examen-diagnostico-2

1. Las metodologías ágiles son cíclicas, habiendo un entregable funcional de algún requisito en cada ciclo.
   
2. Los requerimientos funcionales definen las funciones que el sistema debe de hacer. Por ejemplo: permitir a un usuario hacer una compra con tarjeta de crédito. Los requerimientos no funcionales son aquellos que describen las cualidades del sistema. Por ejemplo: límites de peticiones por minuto.

3. Es el modelo en donde las tareas se dividen entre el proveedor del servicio (el servidor) y los que demandan dicho servicio (el cliente)
Estos se comunican mediante algún protocolo, como el http, donde hay diferentes funciones de solicitud para acceder, enviar  o modificar datos.

4. Las bases de datos relacionales se deberían de utilizar cuando el sistema tiene una estructura bien definida, mientras que las no relacionales pueden usarse en sistemas más flexibles y escalables o donde se prioriza la velocidad para el acceso de datos.

5. Es un conjunto de reglas que hacen uso del protocolo http para las peticiones entre el cliente y el servidor. Manipula los recursos con las diferentes funciones http como get, post, put y delete. Juega un papel fundamental en la integración entre la app y los servidores ya que funciona como un puente entre ambos.

6. Es importante para tener un control de los cambios realizados en el proyecto por el equipo por medio de ramas. El merge conflict es cuando hay una inconsistencia en los cambios realizados en algunas líneas de código al momento de de hacer un merge.

7. Son pruebas de cada función específica en un software, es importante ya que permite detectar algún error antes de llevarlo a producción.

8. El encapsulamiento son las funciones que permiten acceder a los métodos para acceder y modificar a los elementos de una clase. El polimorfismo es la capacidad que tienen los objetos de una clase para comportarse de manera diferente en cada invocación.
Estos dos conceptos ayudan a crear un código más mantenible ya que hacen el código más legible y reutilizable.

9. Es el patrón que separa la lógica del sistema, la interfaz y la interacción del usuario en tres componentes: modelo (donde se gestionan los datos y define las reglas de negocio), vista (lo que ve el usuario) y controlador (un intermediario entre los anteriores). 
Esto ayuda en la organización del código separando de manera más sencilla las responsabilidades y su mantenimiento.

10. La autenticación identifica que el usuario es quien dice quien es, mientras que la autorización controla qué funciones puede realizar ese usuario en la aplicación.
